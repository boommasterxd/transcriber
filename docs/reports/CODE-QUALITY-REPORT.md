## Existing Decisions and Remaining Limits

- Preserve cloud BYOK, independent processing stages, Drift, arm64 packaging and explicit audio ownership from the [accepted ADR](../decisions/cloud-byok-and-drift.md). Serialized identifiers and database schema compatibility are retained.
- HTTP cancellation of custom injected clients requires their transport to support abortable requests. Response consumption is cancelled regardless. An uncooperative Android provider can occupy the single bounded import worker; forced thread termination is not attempted.
- Real Android share, microphone, IME/editor, permission, secure-storage and release-signing checks remain device work. Instrumented tests were compiled, not run. No configured isolated emulator/device, headed Android flow, manual accessibility assessment or device ANR/performance measurement was available.
- Active-dictation backspace remains an Android verification concern, not a confirmed restoration defect: the mock does not actually edit an input field. Test selections, Unicode, active/paused composition and later provider updates in supported editors.
- Removing the broad Gitleaks exclusions revealed three pre-existing `gcp-api-key` records in historical `app/google-services.json`. On 2026-10-19, the project owner confirmed that the keys are no longer usable. Exactly those three immutable commit/path/rule/line fingerprints are now excepted in `.gitleaksignore`; full-history and current-tree scans pass. No provider-authentication check, credential rotation or history rewrite was performed. See [security](../security.md#historical-scanner-exceptions) for the confirmation and scope.
- No real provider requests, production credentials/data or hosted workflow dispatch was performed. The project owner explicitly requested committing and pushing the complete local changes, creating a PR and squash merging with the existing administrator bypass while skipping hosted CI for this integration because of cost. The commit uses `[skip ci]`; actual hosted Slim compatibility and final PR checks remain unverified. Required checks and ruleset settings are unchanged; this one-time instruction does not authorize future bypasses.
- Existing setup and performance reports and unrelated README/license work were preserved. Their findings are not automatically proof of the current implementation. No monetary savings, complete platform coverage, legal compliance or comprehensive security assurance is claimed.
